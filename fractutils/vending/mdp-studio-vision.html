Vision · Three Products · One Spine

Three Svelte products on one MDP spine

Every diagram in this repo — interactive editor output, re-skinned editorial SVG, markdown-embedded figures — is a Model Diagramming Protocol document plus a style-guide skin. Build the spine once; each product is a different face of the same contract.

00The thesis in one picture

The repo already proved the hard parts: @eraserlabs/layout routes orthogonally with zero dependencies, MDP validates documents against JSON Schema per tag, and diagram-design owns the editorial skin. What's missing is a living layer — the same documents, interactive in the browser, branded on demand, and embedded in real documentation sites. Svelte is the thinnest possible layer that adds interactivity without breaking the static-first contracts.

01Why Svelte 5, specifically

The constraints pull toward Svelte

  • SSR is script-free HTML. diagram-design's contract ("static by default, no runtime JS") maps to prerender + SSR output — hydration adds interactivity only where a product is interactive by design (the Studio).
  • Runes model the render pipeline. The repo's own pipeline is measure → layout → apply. That is literally $state (boxes) → $derived (routes) → $effect (DOM write-back).
  • Actions are the missing "behavior layer." MDP templates hold markup+CSS and forbid script. Svelte actions (use:drag, use:measure) attach behavior outside the data — the exact seam the protocol wants.
  • Snippets + schema = generic inspector. The tag registry is JSON Schema. A single <SchemaForm> renders an editor for every tag, current and future.

Honest note: the browser router needs entity boxes, not DOM measurement — the Studio's client pass keeps its own measured-box store and calls @eraserlabs/layout directly. No Chromium in the browser; Chromium (via @eraserlabs/server) remains the authority for PNG.

02Product 1 — MDP Studio: the flagship canvas editor

A SvelteKit app where diagrams are documents you edit, never pixels you redraw. Four load-bearing features: 4px-snap drag, schema-driven inspector, live routing, and the measured-JSON roundtrip. Every gesture produces a valid MDP document — the same one the CLI and server already accept.

The four load-bearing features

4px-snap drag — use:drag

A Svelte action on each node group: pointerdown → capture, pointermove → draft $state, pointerup → commit to the document. Snap = Math.round(v/4)*4, applied to the node's top-left and its container-relative position so containment stays coherent. Draft position routes live (nice feedback); committed position reroutes with pinUnaffectedRoutes so untouched edges don't wiggle.

Schema-driven inspector — registryInfo()

One <SchemaForm schema={tagSchema('Icon')}> walks the JSON Schema: enum → radio/select, x-palette → palette-token dropdown that also accepts raw colors, x-content → textarea with the policy shown, geometry → numeric steppers labeled "minimums". New tags in a library appear in the palette with zero UI code.

Live routing

LayoutManager runs in a worker-adjacent store; boxes come from use:measure (authored size = floor, content can grow). Edge <path d> is a $derived of routed points; labels get the same mask treatment (rect + 2px clearance) as the server renderer so client and PNG agree.

Measured-JSON roundtrip

The store's serialized form is the split envelope {entities, connections} — authored properties verbatim plus final boxes as new floors. Save → file; load → render again. An LLM can read the saved JSON, edit it, and the Studio reopens it — the same loop GETTING_STARTED.md promises, now interactive.

The server split (authoritative pixels)

Walk the interaction

  1. Drop or start. Load diagram.json, or start empty from the palette. The tree mirrors containment (containerId), never z-order.
  2. Drag "api" inside "backend". Draft state routes live; on commit the document gets a new authored x,y snapped to 4; contained siblings stay put; the group's minimums grow only if the member escapes them.
  3. Select the edge. The inspector shows Relationship fields: arrowheads, ports, connectorStyle. Flip to straight and watch the corridor router hand off to straightConnectionEndpoints.
  4. Hit "Validate". Errors carry JSON-pointer paths (/entities/2/icon) that deep-link to the tree row and flash the node.
  5. Hit "PNG". POST to /render; warnings stream back into the lint panel; the preview lands in a drawer.
  6. Save. What's written is the measured roundtrip JSON — reopening it reproduces the canvas, byte for byte.

05Product 3 — MDsveX diagram blocks: diagrams as docs infrastructure

    
Authors write a fenced block; the build compiles it to a static SVG asset. Zero runtime JS, typed data, and a build-time lint that fails CI before a bad diagram ships.

    
---
title: Billing architecture
---

```diagram
type: architecture
skin: acme            # profile slug → tokens.json
size: doc-wide        # output-spec ramp: viewBox + type ramp
data:
  entities:
    - { tag: Shape, id: web, x: 40, y: 60, texts: [{ text: "Web App" }] }
    - { tag: Icon,  id: db,  x: 280, y: 65, icon: postgres }
  connections:
    - { from: web, to: db, endArrowhead: triangle, label: "SQL" }
```

    

      

        
Build pipeline

        
    
          
  1. remark diagram-block plugin parses the fence (YAML or JSON) → AST node.
    2. 
          
  2. Validate with the tag registry at build time — errors are compiler errors with file/line, the same structured issues the CLI prints.
    3. 
          
  3. Render via one of two swappable backends: (a) @eraserlabs/diagrams server-side pass → PNG/SVG buffer, or (b) the Svelte SSR renderer → pure SVG string.
    4. 
          
  4. Emit hashed asset + <img>/<picture> with intrinsic width/height (no CLS), and inline <title>/<desc> for a11y — reusing the diagram-design accessible-name contract.
    5. 
          
  5. Write .registry.json sidecars for block-decomposition diagrams, same as --registry.
    6. 
        

      

      

        
What makes it more than an include

        
    
          
  • Typed data: YAML is validated against tagSchema(tag) — a typo'd endArrowhead fails the build with a did-you-mean, not a silent render.
    • 
          
  • Skin-aware: skin: acme pulls profile tokens; the same doc builds branded for each client in a multi-brand docs monorepo.
    • 
          
  • Deterministic: static frame only; the motion contract's ?motion=static semantics are the only mode a docs site ever emits.
    • 
          
  • Diffable: diagram changes show up in PRs as YAML diffs, not binary churn.
    • 
          
  • Cached by hash: unchanged fence → unchanged asset hash → instant rebuilds.
    • 
        

      

    

    
The compounding trick: the fence's data is a plain MDP document. The same file pastes into MDP Studio for interactive editing, and eraser-diagrams render consumes it in CI unchanged. Three products, one format — that's the thesis made literal.

08Where this could go wrong, and the guardrails

    

      
Client routing ≠ server routing
Risk: the browser pass and Chromium measure differently (fonts!). Mitigation M1's property test pins the router to identical boxes; M4's save/load byte-identity plus --fonts-style font loading keeps drift visible. The PNG stays authoritative.

      
Fonts shift measurement
Risk: Geist/Instrument Serif load late, boxes move after route. Mitigation mirror the render contract: document.fonts.ready before commit-mode re-measure; draft mode may be approximate, commit never is.

      
Schema drift between app and registry
Risk: hand-written inspector fields lag new tags. Mitigation the inspector is generated from tagSchema() only — no hand-written per-tag forms allowed (lint forbids them).

      
Blocks hide complexity from authors
Risk: YAML diagrams get unwieldy. Mitigation the fence documents are MDP files — round-trip them through MDP Studio when they grow, paste back, keep the diff textual.

      
Two renderers, one truth
Risk: Svelte SSR SVG and Chromium PNG disagree visually. Mitigation blocks default to the Chromium backend (backend a) until the Svelte SVG backend passes the same screenshot-diff harness the repo uses for lint-render.

      
Scope gravity toward "full editor"
Risk: multi-select, copy-paste, undo forests eat the calendar. Mitigation the milestone gates say no: M2–M4 cover single-select gestures only; anything else is post-M9 by explicit decision.

    

    
Definition of done for the vision

    
    
      
  • A diagram edited in the Studio, re-skinned by the Token Studio, and embedded via a fence block is the same document at every step.
    • 
      
  • Every artifact each product emits is itself a valid input to every other product and to the CLI.
    • 
      
  • Zero runtime JS on docs pages; full keyboard a11y in the Studio; WCAG AA enforced at token-write time.
    • 
      
  • Each milestone's gate ran green in CI before the next began — no "temporarily skipped" tests.
